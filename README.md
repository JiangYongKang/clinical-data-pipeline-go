# 临床数据接入与去标识化管线

本地可长期运行的 Go 管线：把来自不同来源系统的患者事件归一化为统一模型，
身份归并、去标识化编号与已提交结论持久落在本地，跨重复导入、并发导入与
跨进程重启保持稳定可复现；批次失败整批不留痕，修复后重放与一次性成功一致。

## 结构

- `internal/model` — 统一事件模型、拒绝原因（`RejectReason`）与数据质量判定
- `internal/source` — 两类来源的解析、严格校验，以及按对象边界的多对象 JSON 切分
- `internal/identity` — 身份归一化/归并/冲突判定、事务式登记、去标识化映射、导出与反查
- `internal/state` — 本地持久状态：原子快照落盘、权限收紧、进程锁
- `internal/pipeline` — 批次处理：去重、来源冲突判定、乱序取舍、提交/回滚（内存版与持久版）
- `cmd/pipeline` — 本地运行入口（摄入 / 导出 / 显式反查）

## 来源、JSON 形态与归一化规则

**结构化文本**（管道分隔，7 段；`.txt` 按行切分）：

```
EVT|<eventID>|<patientID>|<eventType>|<code>|<RFC3339时间>|<值>
```

**资源型 JSON**（声明结构，多余字段即拒绝）：

```json
{"resourceType":"Observation","id":"...","sourceSystem":"...","subject":"...",
 "code":"...","effectiveDateTime":"<RFC3339>","value":"...","attrs":{"birthDate":"..."}}
```

一个 `.json` 文件可以是任意一种形态，按**资源对象的词法边界**切分，缩进、
换行、单文件多对象都不会导致整批报错：

- 单条对象（可排版成多行）；
- 顶层数组 `[ {...}, {...} ]`；
- 多个顶层对象顺序排列（允许逗号分隔）。

切分只放宽“排版”，不放宽“结构”：每个片段仍单独严格校验，多余字段、必填
缺失、时间非法、编码非法各自给出可区分的拒绝原因；截断/括号未闭合的片段
产生 `MALFORMED`，同文件其余完好对象仍可摄入。

**来源系统**（去重命名空间）优先级：记录内 `sourceSystem` > 投递级缺省
（CLI 取文件名去扩展名）> 兜底 `local-default`。

归一化产出 `NormalizedEvent`：`EventID / SourceSystem / CanonicalPID /
DeidentifiedID / EventType / Code / OccurredAt(UTC) / Value`。

拒绝规则（不静默丢弃、不按默认值吞掉，原因可区分）：

| 原因 | 触发 |
|---|---|
| `MALFORMED` | 空消息、未知来源类型、JSON 片段词法不合法（截断/括号未闭合） |
| `STRUCTURE_MISMATCH` | 段数/类型头不符、JSON 含未声明字段、resourceType 非 Observation、时间非 RFC3339 |
| `MISSING_FIELD` | eventId / patientId / eventType / code / occurredAt 缺失 |
| `INVALID_CODE` | 编码不在白名单（HR、BP-SYS、BP-DIA、TEMP、SPO2） |
| `IDENTITY_CONFLICT` | 同一规范患者键的身份属性冲突 |
| `EVENT_CONFLICT` | 同一来源系统内同事件号，但时间/编码/取值不一致，无法判定是否同一事件 |

## 身份合并、去标识化与冲突

- **归一化**：患者标识去首尾空白、忽略内部空白与 `-`/`_` 分隔符、统一大写，
  `MRN-123`、` mrn 123 `、`mrn_123` 稳定归并为规范键 `MRN123`。
- **身份冲突**：双方都提供同一身份属性（`birthDate`、`familyName`）且不一致时
  明确拒绝，绝不任选其一；一方未提供视为信息缺失并登记新值。身份登记发生在
  **批次事务副本**上，整批失败即丢弃，注册表不会留下“登记了一半”的痕迹。
- **去标识化**：`DeidentifiedID = "PAT-" + SHA256("deid-v1:"+规范键)[:16]`，
  纯函数推导，无随机性；重复/并发/跨进程导入同一患者恒得同一 ID。
- **事件去重与来源冲突**：去重键为 `(来源系统, 事件号)`。不同来源系统的同号
  事件属不同命名空间，**互不顶掉、不静默合并**；同一来源系统内同号事件若载荷
  （患者、类型、编码、时间、取值）完全一致则按重复幂等处理；若对不上则以
  `EVENT_CONFLICT` **明确拒绝并整批回滚**，不随便挑一个。
- **乱序取舍**：状态键 `(来源系统, 规范患者键, 事件类型, 编码)`，按
  `(OccurredAt, EventID)` 字典序取最大者，与到达顺序无关。

## 持久状态：位置、原子性与权限边界

状态默认落在 `./.pipeline-state`（可用 `-state` 指定）：

| 路径 | 内容 | 权限 |
|---|---|---|
| `<state>/` | 状态目录 | `0700`（仅属主可进入） |
| `<state>/state.json` | 去重集合、每键最新结论、重标识映射（规范键↔去标识化 ID、首次原始标识） | `0600` |
| `<state>/state.lock` | 跨进程排他锁（flock） | `0600` |
| `<state>/state.json.tmp` | 提交时的临时文件，正常情况下不存在 | `0600` |

- **原子提交**：每批“写临时文件 → fsync → rename 原子替换 → 目录 fsync”。
  写到一半进程被杀：要么保留旧 `state.json`，要么是完整新文件，绝不出现半截
  文件；重启时残留 `.tmp` 被清理，状态文件若损坏（JSON 不完整/版本不符）
  **直接报错拒绝启动**，不会被当成空状态吞下而覆盖历史。
- **提交顺序**：整份新状态（含本批身份快照）先落盘，再切换内存。崩溃窗口内
  重启也不会丢失本批身份或产生重复登记。
- **权限**：映射含可还原信息，目录 `0700`、文件 `0600`，同机其他用户不可读；
  打开已存在目录也会重新 `chmod` 收紧。
- **多进程**：同一状态目录同时只允许一个管线进程持有（`flock LOCK_EX`），
  第二个进程立即报 `状态目录已被其他进程占用` 退出，避免并发写坏状态。

### 可复核导出与本地反查（适用范围）

- **导出**：`-export <path>` 导出全部 `去标识化ID / 规范键 / 首次原始患者标识`，
  用于本地核对。导出文件 `0600`、原子写，文件头自带“含可还原信息、请勿外传”
  警告；这是人工复核通道，不是对外接口。
- **反查**：按去标识化 ID 反查原始患者标识默认**关闭**，必须显式带
  `-reidentify <PAT-...>` 才执行，仅用于本地排查；常规摄入输出路径不含原始
  患者标识。

## 本地复现与验证

```bash
go build ./...                 # 编译
go test ./... -v -race         # 全部测试（含竞态检测），日志打印关键标识与判定依据

# 端到端：目录内 .txt 按行、.json 按对象边界处理，每个文件为一批；
# 文件名（去扩展名）是该文件的投递级来源系统。
go run ./cmd/pipeline -dir ./indir -state ./.pipeline-state

go run ./cmd/pipeline -state ./.pipeline-state -export ./mapping.json   # 本地核对导出
go run ./cmd/pipeline -state ./.pipeline-state -reidentify PAT-XXXX...  # 显式反查（仅排查）
```

建议的手工复现路径：

1. 准备多行单对象、数组、多对象序列混排的 `.json` 与多行 `.txt`，跑首轮；
2. 不改输入再跑一次（或换进程/隔几天），确认编号、每键结论、dedup 数不变；
3. 在某批混入同来源同号但值不同的事件，观察 `EVENT_CONFLICT` 整批回滚、
   状态目录无新数据；修好后重放，与“一开始就全对”的目录逐项比对一致；
4. `stat` 检查目录 700 / 文件 600；用 `-export`、`-reidentify` 验证核对通道。

测试覆盖：畸形与缺字段、非法编码、结构不符、多行/数组/多对象 JSON 切分、
跨来源同号不合并与同号载荷冲突、重复投递、乱序到达、身份冲突、并发导入、
批次失败/中断重放与一次性成功一致、跨进程重启编号与结论稳定、原子落盘与
损坏文件拒绝启动、目录/文件/导出权限、跨进程排他锁、大规模输入资源有界。
